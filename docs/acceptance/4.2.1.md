# 4.2.1 acceptance

## Changes under test

Inbox discovery starts at the top, preserves the desktop rail and recognizes the
native selected row. Presence waits for feed content after Home navigation,
recognizes `/reels/` permalinks and backs off empty activities independently.
Ghost reviews preserve per-conversation message choices. The optional reaction
count is bound to the same confirmation as the message run.
Grouped reaction badges resolve the selected individual emoji, including flags,
keycaps and skin-tone variants.
Reaction readiness waits through the native popup transition. **Remove reactions
only** retries the separate pass without invoking Unsend. Cleanup labels retain
their theme color after navigating between tools.

assembly and 1,071 tests, including the inbox/Presence, reaction adapter/pass,
standalone reaction flow and theme regressions.

- PWA: all 11 screenshot states pass.

- Dependency audit: no vulnerabilities reported.

stopped after six conversations with a conversation-change error. The desktop
rail remained mounted. Its selected conversation exposes `aria-pressed=true`.

`/reels/` as well as `/p/` and `/reel/`.

The current Reactions dialog exposes a separate **Select to remove** subtitle
for an own reaction. Its structure matches the ownership predicate. Native
removal through the corrected candidate and managed worker acceptance remain pending.

The commit-pinned `451a9f2` userscript was installed in the existing Chrome
profile. A newest-one Unsend removed exactly one sent message and reported one
verified removal. The follow-up reaction pass opened the native dialog but
stopped before removing the test reaction. Its result remained zero reactions
removed. The added read-only transition regression reproduces that stop; current
fixture success does not yet prove the native failure resolved.

Fixture results do not establish current authenticated Instagram compatibility,
