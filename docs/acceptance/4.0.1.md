# 4.0.1 development acceptance

This is an unreleased source checkpoint, not a stable release. Package metadata
remains 4.0.0 while integration continues. The published 3.1.12 update channel
has not changed.

- Removed Fast from the runner, reservations, preferences, and both in-page UIs.
- Restored visible-first whole-conversation traversal, bounded hover/menu waits,
  pre-dispatch removal observers, and adaptive 1–2 second pacing.
- Retained finite Newest/Oldest ordering, received-message protection, verified
  removal accounting, and Stop settlement without retrying uncertain actions.

  message, two group reels, two reels under an “Instagram user” header without
  a profile link or composer, retained received messages, and an unchanged

  blocked/deactivated-account behavior on Instagram.

## Inbox cleanup

The userscript includes native discovery, exact-ID selection, confirmation,
serial same-tab execution, Pause, reviewed Resume, Skip, Stop, and bounded local job history.
The confirmation discloses that messages sent during execution may also be
removed. Discovery may mark conversations read and does not claim full inbox
coverage without terminal proof.

Navigation requires an exact route and a proven replacement message pane;
changing the URL alone is insufficient. Reused or unproven empty panes stop
before Unsend. This native compatibility gate remains open.

Behavioral fixtures cover cancellation, two selected conversations, account
changes, stale confirmation, busy account locks, interrupted storage, retained
verified counts, and reload without restored authority. Rendered userscript
checks cover dark/light, narrow, short-window, and real 200% zoom layouts with
44px controls and one live region. Screenshots contain synthetic content only.

Native header labels and a name/handle filter are connected to the review list.
Three rendered behavioral gates cover discovery labels, plain versus verified
handle matching, preserved hidden selections, and exact Review/Cancel without
removals. Five populated-list layout states cover the same viewport matrix.
An additional generated-userscript flow selects two synthetic chats, accepts the
exact confirmation and uses the production controller plus shared DM runner.
It removes one own message per selected chat in order, preserves four received
messages, leaves an unselected chat unchanged and stores no action authority.

## Presence

The feature is named **Presence**, with no subtitle. Existing choices compact
after an explicit Build; suggestions and available actions stay together.
Editing reopens the same controls and invalidates the old plan. Keyboard focus
settles on the result summary without a scroll jump; background refresh does
not move it. The manual Follow / Unfollow route remains available.
Nine generated-userscript behavioral gates and five rendered states verify
planning, invalidation, private preference round-trip, keyboard focus and
responsive geometry without native account actions.

Private preference storage preserves allowance, protected handles, hours and
the private-account choice. It does not store plans, captures or authority.
Malformed and newer records have explicit non-destructive handling. The shared
shell change handler no longer clears nested form controls as file imports.
