# 4.1.5 acceptance

## Repairs

- **Unsend:** All-message cleanup processes eligible rows as they load. Only
  finite Oldest selections need a proven oldest boundary before selection.
  Scroller replacement, reversed-layout shrinkage, canvas-only voice messages,
  and playback progress are covered by regression tests. Five failed native
  attempts retire that row in All mode; unresolved removals remain separate
  from verified counts. Stop, thread changes, expiry and restrictions still end
  the run. There is no All-mode message-count quota.
- **Ghost:** Only a tab opened by the reviewed job can attach as a worker.
  Workers wait for React to mount the correct conversation. Settled tabs close
  before replacement tabs open. Failed startup, pre-dispatch menu failure,
  retained-message retries and dispatched outcomes have distinct states. Stop
  allows an already dispatched action to settle without counting an assumption.
  Native discovery handles a persistent inbox rail on a conversation route and
  waits for delayed bottom-of-list pages.
- **Presence:** Native story URLs may omit a slide ID. The active full-size
  media identifies same-route slide changes without retaining the media URL.
  Stories and Notifications close before unrelated activities. Short activity
  visits avoid repeatedly leaving and reopening the same surface. The activity
  log updates during the session and retained account context follows it.

## Automated checks

The source suite passes 1,031 tests. Dependency audit reports no known
vulnerabilities. Extension and web archive-content checks pass.

The release requires the complete Node suite, generated userscript parity,
extension/userscript browser acceptance, Chrome pairing, background fixtures,
45 overlay states, 11 PWA states, dependency audit, hygiene and archive checks.
Windows and macOS package lifecycles run in CI. Release promotion uses the
artifacts of that exact successful main commit; it does not rebuild them.

The generated-userscript Ghost fixture opens three conversations through a
two-window pool with delayed page mounts. It uses real renderer windows and
Web Locks, with a fixture GM transport and synthetic Instagram content. It
checks verified removals, preserved received messages and owned-tab cleanup.
This is not an authenticated Tampermonkey test or proof of browser suspension
behavior. Separate background fixtures cover loaded/hidden, frozen and stopped
states.

Presence fixtures cover ID-less story routes, same-URL Next, return to the feed,
explicit confirmation, log updates, keyboard targets, narrow/short layouts and
true 200% zoom. Existing pixel thresholds remain unchanged.

## Native inspection and remaining acceptance

Read-only inspection of the current authenticated Chrome page confirmed:

- Messages opens the last conversation with a persistent Thread list; no
  separate inbox-return link is exposed in this layout.
- Worker readiness requires the shared message inspector, not just a thread
  URL. Account navigation also accepts the native last-conversation Messages
  control instead of requiring an inbox-only link.
- The loaded story viewer uses an ID-less route and a native playback toolbar.
- Full-size active media must be distinguished from avatars and preview slides.

No real Unsend, Follow, request acceptance or reaction was performed for this
patch. No account, message or media identifiers from inspection are committed.

Before claiming authenticated mutation compatibility, install the exact release
and test approved disposable direct/group messages, including voice notes;
prove multiple removals, Stop and final state; then test two approved Ghost
worker conversations. Verify Presence's enabled mutations separately. Human
screen-reader and persistent-profile Tampermonkey install/update acceptance are
also separate from fixture success.

Instagram can withhold history or suspend a loaded tab. A partial or interrupted
inventory is never described as the entire inbox, and an unresolved removal is
never described as a success.
