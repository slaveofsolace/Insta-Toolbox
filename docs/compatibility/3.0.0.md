# Insta Toolbox 3.0.0 compatibility

This page separates tested account-free behavior from checks that require a real browser profile or platform trust decision.

## Supported delivery surfaces

| Surface | Account-free automation | Manual acceptance still required |
| --- | --- | --- |
| Tampermonkey | Generated parity, synthetic Instagram fixtures, keyboard and layout checks | Current Instagram DOM and persistent profile |
| Chrome extension | Build, fixtures, keyboard, responsive layout, PWA pairing | Current Instagram DOM and persistent profile |
| Web/PWA | Chromium browser flow, offline cache, 11 visual states | Install prompt behavior in each browser |
| Windows desktop | Package contents, confined launch, installer lifecycle | SmartScreen and publisher trust |
| macOS desktop | Universal archive, Mach-O slices, bundle/signature checks, CI launch smoke | Gatekeeper, notarization, and physical Intel hardware |

## Browser targets

- Chrome and Chromium-based browsers are the primary automated target.
- Tampermonkey must have permission to run user scripts on Instagram.
- Firefox and Safari-family userscript behavior is not claimed until recorded in this file.
- The hosted PWA requires HTTPS. Self-hosted development may use a loopback HTTP origin.

## Layout targets

The overlay matrix covers 45 states, including narrow custom panels, mobile landscape, short laptop viewports, light and dark themes, forced colors, keyboard movement and resizing, and true Chromium 200% zoom. The PWA matrix covers 11 states.

Passing screenshots prove the tested fixtures and geometry. They do not replace a human screen-reader walkthrough or prove that Instagram has not changed its live DOM.

## Instagram boundary

The overlay uses the session already active in the Instagram tab. It does not accept passwords or export cookies. Mutual Checker uses a fixed GET-route allowlist and bounded pagination. Follow, Unfollow, and Unsend require exact action-specific confirmation and stop on ambiguous or changed state.

Instagram may change its interface or unsupported web routes without notice. The weekly compatibility workflow exercises synthetic, account-free fixtures only. Record live read-only checks in [the 3.0 acceptance record](../acceptance/3.0.0.md).

## Package trust

- Windows packages are unsigned unless a release says otherwise.
- macOS packages are ad-hoc signed but not notarized unless a release says otherwise.
- `SHA256SUMS.txt`, the SBOM, and GitHub provenance attest the released bytes; they do not provide an operating-system publisher identity.

## Local data compatibility

Version 3.0 changes public names, userscript identity, and companion-local
identifiers. It does not read, migrate, or delete 2.x browser or desktop state.
It starts clean and leaves the older local data untouched. Export anything you
want to keep, and do not run 2.x and 3.0 companions together.
